# HEPSlide 개선 계획 대조 및 구현 현황

검토일: 2026-11-14 KST. 기준 자료: `HEPSlide_Improvement_Plan_2026-11-13.pdf`의 SAFE01–EXT01 및 A01–A10. 저장소 기준은 `f144bc7`이며, 검토 시작 시 작업 폴더에 있던 미커밋 변경도 포함했다. 문서의 제안과 현재 구현 증거를 구분하고, 실제 설치본에서 확인하지 않은 항목은 완료로 표시하지 않는다.

제품명·저장소·파일 확장자는 현재 SciSlide를 유지한다. 이번 변경은 개발 소스에 반영한 것이며, 새 설치 파일 게시나 1.0 출시 완료를 의미하지 않는다.

2026-11-15 후속 UX 현황은 [실제 0.6.6 GUI 점검](ux-review-0.6.6-2026-11-15.md)과 [두 번째 UX 개선](ux-review-0.6.6-pass-2-2026-11-15.md)에 별도로 기록했다. 두 번째 개선은 편집 중 저장 표시, 수식 초안 검토·저장 안내, 작은 창의 노트 크기·포커스, 문서 비율에 따른 Fit·격자를 다루며 전체 84개 파일/1,112개 회귀 테스트를 통과했다. 아래 수치는 각 단계 당시의 이력으로 유지한다.

## 이미 개선되어 있던 기반

- `.scislide` 0.5.0 아카이브가 본문·수식 원문·자산·그룹·참조와 Local LaTeX 캐시를 보존하고 모델·자산을 검증한다.
- 객체·슬라이드 snapshot, 새 ID 생성과 자산 중복 제거, 내부 이동·슬라이드 순서 변경·Undo가 구현되어 있었다. 시스템 클립보드와 외부 파일 드롭 연결은 별도 미완료였다.
- IndexedDB 복구, localStorage fallback, 수식 미적용 초안, 쓰기 직렬화가 있었다. 저장소 간 최신성 비교는 없었다.
- 본문 `fontFamily`와 독립 수식 `fontSetId`가 분리되어 있었고 Inter·Nanum Gothic 본문 및 세 MathJax 수식 폰트를 제공했다.
- 검토 시작 시 사용자 변경에 인라인 수식의 독립적인 `inlineMathFontSetId`, Latin Modern 기본값 및 관련 테스트·안내가 있었다. 이를 보존했다.
- 이미지/PDF 파일 선택기, PDF 페이지·영역 선택, SVG/PDF/PPTX 출력, 인라인 수식 편집창이 있었다.
- Linux push CI와 같은 커밋에서 다섯 배포 파일을 만들고 체크섬·아키텍처를 검증해 묶는 릴리스 workflow가 있었다. Windows 설치·실행·제거 smoke 경로도 기존 구현이었다.

## 회귀 검증과 실제 검증의 구분

문서 안전성 1차 개선의 로컬 검증은 공식 Node.js 24.22.3에서 실행했다. 후속 검증은 아래 각 단계에 별도로 기록한다.

- 편집기·CLI·저장·출력: 68개 파일, **968개 테스트 통과**, 실패 0.
- 데스크톱·패키징·릴리스: **150개 통과**, 플랫폼 조건에 따른 14개 skip, 실패 0.
- `tsc -b`, Vite 프로덕션 빌드, 독립 CLI 빌드 및 `git diff --check` 통과.
- 브라우저 제어 호스트가 제공되지 않아 실제 화면 조작·스크린샷 검증은 수행하지 못했다. 실제 OS 클립보드·설치본·PowerPoint 검증도 아래의 후속 범위에 남겨둔다.

## 후속 UX 개선

기능 확장 대신 기존 편집 흐름의 선택·시작·피드백을 개선했다. 여러 개를 선택하면 첫 개체의 속성 대신 선택 개수와 그룹·잠금·숨김 상태를 보여 주며, 기존 Arrange 도구나 한 개체의 스타일로 바로 이동한다. 그룹 멤버의 스타일을 따로 열어도 그룹과 Undo 이력은 유지한다. 일괄 삭제의 활성 여부는 첫 개체 대신 편집 가능한 전체 선택으로 판단한다.

빈 슬라이드는 텍스트·수식·그림의 기존 삽입 흐름으로 안내한다. 캔버스 안내는 선택·잠금·텍스트 편집·그리기 상태에 맞게 바뀐다. 메뉴는 키보드 탐색과 닫힘 후 포커스 복귀를 지원하고 다른 메뉴/영역으로 이동하면 닫힌다. 저장 상태에는 로컬 저장 대기/완료와 미적용 수식 초안을 구분하며, 초안이 있으면 전환 확인창에서 파일 저장이 불가능한 이유와 복구 보관 선택을 먼저 안내한다.

독립 UX 검토에서 찾은 삭제된 수식의 초안 잔류와 메뉴 포커스 경계도 보완했다. 삭제한 개체·슬라이드의 초안은 현재 저장 상태와 전환 판단에서 제외하되, 메모리에는 유지해 Undo로 개체를 되돌리면 초안도 다시 편집할 수 있다. 메뉴에서 연 대화상자를 닫으면 숨은 메뉴 항목 대신 트리거로 돌아오며, disclosure에 포커스가 있을 때 Delete·방향키가 캔버스 개체를 바꾸지 않도록 한다.

후속 UX 최종 검증은 편집기·CLI **79개 파일/1,072개 테스트 통과**, 실패 0이다. 선택·빈 슬라이드·메뉴·포커스·저장 상태·초안 삭제/Undo/Redo 회귀를 포함한다. 타입 검사와 production 웹/CLI 빌드, 변경 파일의 서식·공백 검사도 통과했다.

실제 브라우저 연결은 사용할 수 없어 라이브 화면 배치와 OS 상호작용 검증은 남아 있다. 이전 Linux 패키지는 아래에 기록된 입력 스냅샷으로 만든 것이며 이번 후속 UX 소스 변경을 포함하지 않는다.

## 다음 작업 순서

1. 같은 커밋으로 지원 OS별 개발 설치본을 만들고 A01–A10을 실제 발표 자료로 실행한다. 본문/수식 폰트·영문/한글·분수/첨자·PDF 그림·SVG 내장폰트·기존 문서를 포함한다.
2. 구현한 문서별 복구 목록과 전환·초안 보존을 실제 브라우저 quota·다중 창·OS 종료/재시작 환경에서 확인한다. 자동 단위 검증과 실제 기기 결과를 구분해 기록한다.
3. SVG의 알려진 출력 제한 사전 안내는 반영했다. PDF 미지원 폰트의 outline/검증된 변환 지원 확대를 결정한다. PPTX의 폰트 미내장·분리 수식 재배치 한계도 실제 PowerPoint에서 확인한다.
4. 실제 검증 결과를 반영해 1.0 범위를 확정한 뒤 프로젝트 라이선스와 정식 배포·업데이트 정책을 최종 결정한다.

## 후속: 문서별 복구·조기 출력 안내·실제 패키지 검증

문서별 복구 UI는 시작 화면 및 File → Recovered documents에서 접근한다. 새로 열거나 만든 문서는 세션별 복구본을 갖고, 이후 자동 저장은 해당 복구본을 갱신한다. Keep recovery and continue는 미적용 초안을 포함해 최신 복구본을 저장한 뒤 전환하며 실패하면 기존 문서를 유지한다. Discard는 새 복구를 강제하지 않으며 이전 자동 복구본은 명시 삭제할 때까지 남는 정책을 안내했다. 복원한 문서는 원본 저장 경로를 이어받지 않는다.

독립 검토에서 찾은 손상 동일-ID 원문 제거와 다중 창 저장 유실을 보완했다. IndexedDB의 읽기·병합·쓰기를 하나의 transaction으로 묶고, Web Locks가 없는 fallback은 세션별 저장·삭제 key로 분리했다. 같은 ID의 손상 원문도 별도 보존하고 용량에 포함하며, 해당 ID의 명시 삭제만 제거할 수 있다. 대화상자의 CSS 우선순위 및 키보드 포커스를 보강해 테마 화면이나 아래 복구 창이 저장 확인창을 가리거나 포커스를 가져가지 않도록 했다.

SVG 가져오기·교체·드롭·붙여넣기는 알려진 PDF 제약을 일찍 안내하고 선택한 그림의 Inspector에도 유지한다. 실제로 사용되는 폰트·효과를 분석하며, 미사용 내장 폰트는 경고하지 않는다. 실제 글리프 검증과 PDF 미지원 형식의 변환은 별도다. CLI의 문서 인라인 기본 폰트 설정·해제도 연결했고 Electron 캐시에는 의존성의 체크섬을 적용했다.

실제 Linux 패키지 검증 첫 실행은 빌드·.deb 생성·체크섬·추출·CLI 저장/재열기·SVG까지 통과했으나 내장 폰트 그림의 PDF 출력에서 CSSStyleSheet 누락을 확인했다. 이 실행은 실패 이력으로 보존했다. 필요한 CSS 생성자를 제공하고, 현재 검증된 슬라이드의 내장 TrueType 폰트를 PDF 변환과 글자 폭 측정에 함께 등록하도록 수정했다. 측정 상태를 슬라이드별로 제한하고 PDF 작업을 직렬화하며 최종 글리프 검증은 유지한다. 실제 그림 예제의 native 왕복·PDF 내장 회귀도 추가했다.
