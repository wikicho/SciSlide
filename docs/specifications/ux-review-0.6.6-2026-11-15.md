# SciSlide 0.6.6 실제 GUI UX 점검 — 2026-11-15

공식 0.6.6 Linux 앱에서 불편을 재현하고, 별도로 패키징한 미게시 수정본에서 같은 조작을 반복했다. 이번 변경은 `codex/ux-review-0.6.6`의 후속 개선이며 공개된 v0.6.6 태그·설치본은 변경하지 않았다.

## 실행 기준

- 기준 소스: 공개 태그 v0.6.6, commit `5cf77783128bc739bd1ec8241b7d3d0454da47e5`.
- 기준 설치본: 공식 `SciSlide-0.6.6-linux-x64.deb`, SHA-256 `59437d5acb12d86c60f485f6d7f6ea4967b7aaf72c2cebbfb0b950fb0502ab17`.
- CUA 연결을 사용할 수 없어 사용자가 허용한 Xvfb·Playwright 방식으로 실제 Electron 창을 실행했다. 웹 앱 모형이나 jsdom 결과를 실제 GUI 결과로 표현하지 않는다.
- 기준 앱과 수정본은 각각 독립 프로필과 테스트 파일을 사용했다. 기존 사용자 문서·프로필과 release 산출물은 유지했다.
- 시스템 설치 없이 추출본을 실행하기 위해 테스트 사본에서만 바이트가 동일한 기존 root 소유 sandbox helper를 참조했다. Chromium sandbox를 유지했고 `--no-sandbox`는 사용하지 않았다.

## 편집·저장·출력 확인

기준 앱과 수정본 모두 실제 캔버스에서 한글·영문과 `$U(1)$`, `$m_\chi$`, 분수 인라인 소스를 편집했다. 편집 중 Ctrl+S로 실제 `.scislide` 파일을 쓰고, Ctrl+O로 다시 읽어 원문·독립 수식과 Undo 초기화를 확인했다. GUI의 PDF 내보내기로 실제 파일을 만들고 텍스트 추출과 페이지 렌더링을 검사했다.

양쪽 PDF는 1페이지이며 렌더링 결과가 픽셀 단위로 동일했다. renderer의 page error와 console error는 없었다. 기존 Poppler의 jsPDF `Adobe-Identity-H` 진단은 실행 기록에 남겼으며 렌더링과 텍스트 검사는 통과했다.

파일 선택 대화상자는 Playwright의 Electron main API로 테스트 파일 경로만 지정했다. 편집기, IPC, 아카이브 직렬화, 파일 쓰기·읽기와 PDF 출력은 실제 구현을 실행했다. 네이티브 파일 선택 위젯의 수동 조작이나 OS IME 조합키 입력까지 검증한 것은 아니다.

## 다음 UX 점검 후보

미적용 수식 초안이 있는 직접 Save의 안내, 손상 복구본이 용량을 차지할 때의 원문 보존·명시 정리 UX를 후속 후보로 남긴다. 이번에는 자동 삭제나 복구 보존 정책을 바꾸지 않았다. Windows·macOS의 실제 화면, 네이티브 파일 선택 위젯, OS IME와 실제 시스템 클립보드 조작은 별도 확인이 필요하다.
