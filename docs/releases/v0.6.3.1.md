# SciSlide 0.6.3.1 — macOS Local LaTeX and headless agent CLI

This development prerelease adds isolated Local LaTeX compilation on macOS and packages the headless agent CLI for creating, editing and exporting native presentations. Existing editor behavior and the native `.scislide` document format **0.5.0** remain unchanged.

## What's new

- **macOS Local LaTeX:** compile equations explicitly with installed LaTeX or XeLaTeX, `dvisvgm` and `kpsewhich`. MacTeX/BasicTeX's `/Library/TeX/texbin` is detected automatically. Choose **Local LaTeX · Installed packages**, set the preamble/source, then choose **Compile with LaTeX → Apply equation**. The worker permits read-only system TeX/font/runtime files and one writable temporary job directory. Home files/packages/fonts, network access, process forking and unapproved executables are blocked. Actual containment probes must pass before compilation is enabled. Jobs have wall/CPU/file limits, cancellation and a parent RSS watchdog; the watchdog detects memory overages by polling rather than enforcing an instantaneous hard quota. No Xcode tools or separate sandbox package are needed by the application.
- **Headless agent CLI:** `scislide --cli schema`, `create`, `inspect`, `validate`, `apply`, `unpack`, `pack` and `export` operate without opening the editor. Agents can apply validated JSON batches, import local SVG/PNG/JPEG figures and export SVG/PDF. Installed launchers use the bundled runtime; a separate Node installation or AI account is unnecessary. Output replacement is explicit, with dry runs and file-hash freshness checks. The standalone `dist-cli/` build runs with Node.js 22 or later. See the [agent CLI guide](https://github.com/wikicho/SciSlide/blob/v0.6.3.1/docs/AGENT_CLI.md).
- **Four-part app versions:** packaging and the new update CLI support the requested `0.6.3.1` version alongside three-part versions. This changes application version handling, not the document format.

The CLI preserves valid saved Local LaTeX results but does not launch TeX compilers or installed AI providers. Its headless export uses bundled fonts; unavailable custom fonts or unsupported glyphs produce an error. Windows Local LaTeX remains unavailable. Linux Local LaTeX continues to require working bubblewrap isolation and installed TeX tools.

## Upgrade from v0.6.3

**Download and install v0.6.3.1 directly from this release.** The v0.6.3 update CLI accepts only three-part versions and ignores the `v0.6.3.1` tag. After this manual upgrade, the new CLI can compare both three-part and four-part versions and download verified matching installers. It still prints the installation command for a separate installation step; it does not install automatically. Earlier v0.6.3 packages contain neither the macOS worker nor the agent commands.

## Validation and compatibility

The release source passed **839 web tests** and **142 Linux desktop, packaging and release checks** (three platform-dependent skips). The compiler backend also passed **21 native macOS tests** on `wikicho-macbookair` (Apple Silicon). The native checks covered LaTeX/XeLaTeX rendering, filesystem/home/symlink/APFS alias isolation, network/exec/fork denial, resource checks, concurrency, cancellation and recovery. That run exercised the backend modules with the installed Electron runtime; it did not install the new package or validate the complete editor GUI. Intel macOS and complete physical Windows/Linux editor journeys remain separate validation work.

New saves retain native format **0.5.0**; formats **0.1.0–0.4.0** still migrate on opening. Use **Save As** to preserve an older original. Saved valid Local LaTeX vectors remain viewable and exportable without TeX. Signing/notarization, automatic installation, hosted APT/Snap distribution, PPTX/HTML export and advanced animation remain future work.
