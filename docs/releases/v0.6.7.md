# SciSlide 0.6.7 — Clearer save feedback and responsive editing

This development prerelease includes two rounds of UX improvements checked in real Linux Electron windows after v0.6.6. Native presentations retain format **0.5.0**. Existing v0.6.6 installers and tags remain unchanged.

## Saving and local recovery

- **Honest save status while typing:** editing text directly on a slide immediately shows “Unsaved changes.” Escape restores the previous status; Save commits the pending edit before writing the presentation.
- **Actionable equation drafts:** the local-draft badge opens a relevant equation and focuses its source. It prefers an editable draft; if the available draft is hidden or locked, it opens Layers and explains what to show or unlock without changing those flags.
- **Clear draft-save feedback:** Save writes applied presentation content and explicitly reports drafts that remain local and absent from the file. Applying a draft includes it in subsequent saves. Local recovery and document-transition protections remain in place.
- **Persistent recovery-history warnings:** a failed history save remains visible after the transient notification disappears, distinguishes current-workspace recovery from history, and offers a direct review action. A later successful save clears the warning; delayed responses from older sessions cannot replace current state.

## Navigation, layout, and selection

- **Predictable Export menu:** Export closes when another menu opens, when focus leaves, or when clicking outside. Escape closes the menu, preserves the canvas selection, and restores focus to its trigger. Dialogs and presentation shortcuts keep their existing routing.
- **Small windows and long titles:** the editor follows the actual window content height; titles stay within the header and canvas heading, with full text available in a tooltip. Required controls and speaker notes remain reachable at the minimum desktop window size.
- **Responsive speaker notes:** the resize range follows available space while retaining the preferred height for larger windows. An unavailable zero-height input leaves the tab order; focus returns to the notes toggle only when necessary.
- **Fit for custom slide sizes:** Fit uses the document's dimensions and accounts for borders instead of assuming 16:9 or imposing an oversized minimum paper width. The initial zoom is labeled “Fit”; percentages describe zoom relative to that fit.
- **Accurate visible grid:** both axes follow the 20-unit document grid at the current zoom, including 4:3 and portrait slides.
- **Group-lock clarity:** selecting a member reflects locks inherited from its group. Unlock group clears that group's locks while preserving independent object locks; Undo restores the previous group state.

## Validation and limits

The final pre-release source suite passed **1,112 editor/CLI tests across 84 files**, **220 desktop/packaging checks**, and **20 release checks** on Node.js 24, with three platform-dependent skips and no failures. TypeScript and production web/CLI builds passed. Regression checks cover save feedback, pending text, local drafts, cross-slide review, hidden/group-locked targets, menu focus, recovery warnings, responsive notes, and keyboard focus. Platform jobs independently build and verify all five distributions from the release commit before publication.

Real Linux Electron previews were tested under Xvfb with isolated profiles and document copies. Checks include minimum and larger windows, 960×720 and 720×960 slides, grid spacing at Fit and 120%, pointer movement, and canvas editing of Korean, English, and inline math followed by native Save, Open, and PDF export. The final preview preserved editable source, reset Undo on reopen, rendered a one-page PDF without clipping, and reported no renderer page or console errors. File-dialog return paths were automated; actual archive validation, IPC, file IO, and export implementations ran unchanged.

Those preview records identify their exact source inputs and are not claims of manual installation or full OS integration testing. Windows/macOS screen interaction, native file-picker widgets, IME composition, system clipboard interoperability, file associations, and update-installation journeys remain separate validation. macOS installers remain unsigned and unnotarized; Windows distributions remain unsigned. Existing Local LaTeX, SVG/PDF font-format, and PPTX limitations still apply.
