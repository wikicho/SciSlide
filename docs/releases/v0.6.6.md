# SciSlide 0.6.6 — Safer editing, independent typography and clearer controls

This development release consolidates the document safety, external input, typography, output and usability improvements prepared since v0.6.4. Native presentations retain format **0.5.0**. The existing 0.6.4.1 notes, packages and validation records remain historical snapshots.

## Documents and recovery

- **Save, discard or cancel:** opening another file, creating a presentation and closing the desktop editor check for unsaved work. A new Save destination is adopted only after the candidate document passes validation and the transition is accepted. Cancelled or failed reads/saves preserve the active document and destination; replacing a document resets Undo/Redo.
- **Session boundaries:** delayed image imports, clipboard reads, saves and equation work cannot change a different document session, including when reopening a document with the same ID.
- **Recovery history:** startup compares valid IndexedDB and localStorage snapshots and prefers the newest dated copy. File → Recovered documents and the startup screen expose session copies with unapplied equation drafts. Restoring creates an independent session without an original file destination.
- **Preserve before continuing:** Keep recovery and continue writes the current copy before a transition; a failed write keeps the current document open. The bounded history does not automatically evict old work, and removal requires confirmation. IndexedDB updates are transactional across windows; the fallback separates session records and preserves damaged raw entries for explicit removal.
- **Draft state:** deleted objects and slides no longer leave active unsaved-draft warnings. Undo can restore their retained drafts. File-save state, pending local recovery and unapplied equation drafts have separate labels and transition guidance.

## External input and editing controls

- **System clipboard:** copied objects and slides retain editable structure, groups, notes and referenced assets. Paste uses current system text and PNG content, including screenshots, rather than a stale internal copy. Failed clipboard writes preserve cut originals. Focused text fields and dialogs keep native clipboard and history behavior.
- **File drops:** PNG, JPEG and SVG batches keep file order, insert at canvas coordinates corrected for zoom/scroll, and form one Undo step. A single PDF opens the page picker; a single `.scislide` file uses the safe document transition. Invalid or failed batches leave the document unchanged, and unsupported URL drops explain accepted inputs.
- **Selection clarity:** multiple selections show their count and group/lock/visibility state, with direct access to Arrange tools or one member's style. Group-member editing preserves the group and history. Batch deletion considers the editable selection instead of only its first object.
- **Starting and navigating:** empty slides offer text, equation and figure actions, and canvas hints follow the current editing state. Toolbar menus open exclusively within a toolbar, support arrow keys, Home/End and typed search, skip disabled actions, and close when focus leaves. Escape and completed actions return focus to a visible trigger while dialogs retain their own focus. Plain menu keys do not mutate canvas objects; global help and presentation shortcuts remain available.

## Typography and vector output

- **Independent defaults:** body text, standalone MathJax equations and inline mathematics have separate preferences. Inter and Nanum Gothic remain the bundled body choices. Inline mathematics defaults to Latin Modern and can use STIX Two or Fira Math. Changing body or standalone-equation fonts preserves the inline choice.
- **Inheritance and persistence:** existing text can keep an explicit font or follow the deck default. Text objects can independently inherit or override the inline font. Copies between documents preserve the source's effective typography. The agent CLI can set or clear `theme.inlineMathFontSetId`; clearing restores the Latin Modern default.
- **Visible source editing:** inline source controls use bounded placement and scrolling outside oversized or rotated frames, including zoomed slides.
- **Imported SVG consistency:** import and export share restricted stylesheet validation. Supported embedded fonts remain scoped to each figure. Import and the figure Inspector report known PDF restrictions for fonts and effects actually used in visible content; final export still validates actual glyphs.
- **Headless PDF fixes:** supported embedded TrueType figure fonts are registered for both PDF conversion and text measurement. The headless exporter provides the CSS constructors needed by its converter, limits measurements to the validated current slide and serializes PDF work. Real-font native round-trip and vector PDF tests cover the previously failing path.
- **Archive metadata:** the producer version follows the application package version rather than a fixed historical value. It remains separate from the document-format version.

## Packaging and release preparation

Installers default to `release/v0.6.6/<platform>/` and unpacked applications to `release/work/v0.6.6/`. Explicit `--out` directories keep their existing contract. Builds stage and validate outputs before replacing the app, installer, checksum and guide set; recoverable failures restore the previous outputs. Output-boundary symlinks are rejected, and concurrent publication is locked. The organization command previews moves by default, preserves historical artifacts and records verified moves and rollback journals.

Electron archives are checked against the installed dependency's checksum manifest. The Windows TeX discovery fixture uses the host PATH delimiter and executable suffix. The combined release workflow builds all five macOS/Windows/Linux distributions from one source commit, verifies the complete artifact set and includes checksums and platform guides. Prerelease remains the default publication channel; manual stable publication is explicit and marks the release latest only after artifact verification. The updater includes prereleases by default, with `--stable` available.

## Validation and remaining limits

The 0.6.6 source passed 1,072 editor/CLI tests, 209 desktop/packaging tests and 13 release-publication tests, with 14 platform-dependent skips and no failures. Type checking and production web/CLI builds also passed. Platform release jobs independently build and verify their distributions from the release commit before publication.

Automated regressions cover document transitions and save failures, recovery history and damaged entries, clipboard boundaries, drop placement and batch Undo, independent typography, imported-font output, toolbar focus and native dialog return paths. The earlier Linux 0.6.4.1 package passed a recorded 28-step build/extract/packaged-CLI/SVG/PDF check; it predates the final UX changes and does not establish 0.6.6 package or GUI validation. Failed runs and their source provenance remain preserved separately. See the [improvement audit](https://github.com/wikicho/SciSlide/blob/v0.6.6/docs/specifications/improvement-status-2026-11-14.md) and [release directory guide](https://github.com/wikicho/SciSlide/blob/v0.6.6/docs/RELEASE.md) for the recorded scope.

Complete 0.6.6 installation, GUI editing, native clipboard, file association and update-installation journeys on each supported OS require separate validation. macOS installers remain unsigned and unnotarized; Windows distributions remain unsigned. Windows Local LaTeX, unsupported SVG PDF font formats/styles, PPTX font embedding and equation reflow remain limited. Local LaTeX still requires the selected engine/preamble and explicit compilation. Latin Modern support adds a math font, not a body-text font.

The project-source license decision, product renaming and extension/Feynman modules remain separate work. This development release does not declare the 1.0 criteria complete.
