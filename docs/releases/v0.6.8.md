# SciSlide 0.6.8 — Reliable Linux file drops

This development prerelease fixes native file drops onto the white slide canvas. Native presentations retain format **0.5.0**. Existing v0.6.7 releases and validation records remain unchanged.

- **Quick PNG/PDF drops:** the canvas accepts file drags on entry as well as over movement, so releasing immediately after entering a nested SVG target still imports the file. PDFs keep the existing page-selection workflow.
- **Drops while editing text:** dropping a file over the active inline canvas editor finishes and preserves its pending text before importing. Other text fields keep their native editing behavior.
- **Drop-highlight cleanup:** moving between nested canvas elements keeps the highlight stable; leaving the canvas, cancelling the native drag, or completing a drop clears it.

## Validation and limits

Native GTK3 `text/uri-list` drags driven with XTest under Xvfb reproduced quick PNG/PDF drops that were ignored by v0.6.7 and imported successfully in the fix preview at the same landing coordinates. The checks use actual Electron windows, native file-backed drag data and the existing import code, with isolated profiles and file copies. This is representative GTK/Xdnd coverage, not a manual Nautilus test or Windows/macOS drag validation.

The editor/CLI regression suite passed **1,120 tests**. Existing package-signing and platform-validation limits remain in place. Platform jobs build and verify all distributions from the release commit before publication; manual native file-manager and cross-platform editing journeys require separate validation.
