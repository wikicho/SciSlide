# SciSlide 0.6.10 — Save, quit and workspace recovery

This development prerelease fixes the boundary between saving a portable file, closing the editor and resuming local work. Native documents retain format **0.5.0**. The authoring and large-document improvements from 0.6.9 remain available, and earlier releases and validation records remain separate.

## Changes

- A successful native Save checkpoints the current workspace before completing. Closing the editor also waits for its current recovery checkpoint, so an immediate exit does not depend on the autosave delay. Edits made while saving or closing prevent a stale snapshot from being treated as the latest saved document.
- Resume restores the last acknowledged save/download reference and displayed filename. Saved or opened references show **Recovered saved copy**; downloads retain **Downloaded .scislide**. The original native overwrite path is not restored from recovery data; saving a resumed copy can require a file dialog.
- Known later edits remain **Unsaved changes** after restarting. Older backups without enough save information show **Recovered local copy**, and still require a choice before leaving unsaved work.
- Applying pending text before Save preserves the intended file snapshot. Text entered while a save is pending remains newer local work instead of being mislabeled as saved. Cancelled or failed file saves do not advance the saved reference.
- Unapplied equation drafts remain local, survive recovery, and still require Apply before inclusion in a portable file. A local checkpoint failure does not undo a successful file save; feedback directs the user to the saved `.scislide` file.
- Resuming the same workspace reuses its recovery-history session instead of consuming another history slot. Historical recovery copies remain independent and do not inherit an overwrite destination.

## Validation

Ten dedicated App integration regressions cover successful Save and immediate close/restart, awaited checkpoints, later and in-flight edits, Save cancellation/failure, local-checkpoint failure, separate equation drafts, downloads, legacy backups and recovery-session reuse. Library and real canvas-editor regressions cover provenance validation and pending text behavior. Package builds and native GUI checks are recorded separately as they complete; physical Windows/macOS validation remains required.
